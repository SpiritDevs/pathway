# Computer Use is rewritten in Effect

Synara's Computer Use core is plain TypeScript classes behind one thin Effect layer. The core includes `ComputerManager`, the Cua backend, the approval gate, the lease and operation queue, targeting and geometry, the tool gateway and the desktop driver host. Pathway rewrites all of it in Effect, as services with typed errors, scoped resources and Effect concurrency. That applies to the server and to the Electron host code. Swift and Rust stay native. MCP tools are defined with `effect/unstable/ai` `Tool` in a `computer` toolkit. Contracts stay Effect Schema; both repos pin the same `effect-smol` build (`8881a9b`).

Effect is a core requirement for Pathway's TypeScript runtime code, and the maintainers chose it over the lower-risk option of porting the verified classes unchanged. The main risk is that Synara's concurrency behavior (leases, cancellation epochs, held-input release, approval queueing) was proven by roughly 9k lines of tests against the original shape. So Synara's test suites are the behavioral specification: every Synara test case is ported as an `@effect/vitest` case asserting the same behavior before its module counts as done. A behavior change against a Synara case needs an explicit, recorded reason.

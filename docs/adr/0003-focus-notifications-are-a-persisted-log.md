# Thread notifications are a persisted, expiring log, not derived state

Attention events (run finished unsettled, pending approval, awaiting input, failed) are written as notification records to Convex rather than derived on the fly from thread state + `lastVisitedAt`. Persisting was chosen so the feed survives thread-state changes, works across machines, and can show history; the cost is a cleanup obligation: records are deleted when read + 7 days or unread + 30 days, with a hard cap of 200 per user (oldest evicted). The badge counts all unread notifications and opening the tray marks everything read with a Convex watermark, so it clears on every machine. Thread alerts add per-event acknowledgements for individual OS-notification clicks; an event is read when covered by the watermark or its own acknowledgement. Reading never deletes early. Retention rules alone remove records.

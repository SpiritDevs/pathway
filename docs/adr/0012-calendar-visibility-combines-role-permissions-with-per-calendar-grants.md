# Calendar visibility combines role permissions with per-calendar grants

Two new `PermissionKey`s carry the coarse axis — `calendar.read` (use the feature; see own and granted calendars) and `calendar.readAll` (see every calendar in scope without a grant) — and a `calendarGrant` entity carries the fine one, so "viewer access to Darren's calendar and nobody else's" is `calendar.read` plus one grant. Grants name a _calendar_, not a person, because sharing a work calendar while withholding a personal one is the case that matters; the picker groups by owner. A viewer reaches a calendar by owning it, by a grant naming them, or by `calendar.sharing` being `team`/`company` while they hold `calendar.readAll` at the matching scope, and a grant is necessary but never sufficient — `calendar.read` is always also required. An event marked `visibility: "private"` stays owner-only through the existing binary `ownerMembershipId` gate regardless of any grant, and mirrored Google calendars default to private sharing. Free/busy is deliberately absent: the change feed appends one opaque payload per row for every eligible viewer and cannot redact per viewer, so a "Busy" placeholder would have to be written as a second, separately-shared row rather than a redaction — which is the path to take if the resulting unexplained gaps ever need filling.

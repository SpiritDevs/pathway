# Native workspace tools

The thread workspace destination uses the selected environment connection and the thread's effective worktree path. It includes current repository status and diffs; explicit selected-file commits; push, pull and PR creation; branch creation/switching with thread metadata updates; server-previewed workspace moves; file browsing/search/read/edit; terminal command controls and project scripts; PR lists, detail, checks, comments, reviews and provider-supported lifecycle actions.

Inject `PathwayWorkspaceContext`, the environment request callback, and optional dedicated subscription and signed-asset URL callbacks into `PathwayWorkspaceView`. Do not reuse the conversation client's subscription for terminal attachment. Keep the context's mutation readiness current as the connection and active turn change. The context carries no credentials.

Diff lines support local inline review drafts with side/line/rename anchors; comments are sent together with the selected review verdict. Drafts can be edited or removed before submission. Quoted Git paths remain readable but cannot be anchored until their C-style path encoding is supported. Reviewer candidate lists support request and take-back; hosts without candidates accept an explicit reviewer identifier.

PR actions intersect host capabilities, viewer permissions, repository merge methods and current state. Mutations re-read the PR before dispatch. Commit payloads require explicit selected paths and a nonempty message. Branch changes update the thread only after successful checkout and guard its expected worktree location. Workspace moves use the server's preview blockers, rechecked before requesting the move. A move acknowledgement is presented as a request, not completed work.

Complete file reads return a SHA-256 revision. Mobile sends it as `expectedRevision` when saving; the environment serializes compare-and-write operations for the same canonical file so competing Pathway API saves cannot both overwrite a shared revision. Stale and truncated data are refused. Older environments without revision support remain readable and require a server update before editing. External editor/provider processes do not participate in these locks, so their writes cannot be made filesystem-atomic with this API. The terminal embeds the same Ghostty Canvas/WASM renderer as desktop in an offline WKWebView. Raw escape sequences, cursor movement, full-screen buffers, IME/hardware input, selection, copy, bracketed paste and viewport resize use that existing implementation. A selectable transcript remains available for reading with accessibility tools. Streams end when the view's task is cancelled; opening a shell does not imply stopping it when navigating away.

The source and new focused tests have been parsed with Swift. Integrated Apple-platform build/tests and live provider/relay behavior must be verified separately. No environment, Git, file or PR operations were executed during implementation.

## Bundled terminal renderer

`node scripts/ios/build-terminal.mjs` rebuilds `Pathway/Resources/PathwayTerminal.bundle` from the checked-in web Ghostty adapter, its WASM/font artifacts, and `apps/pathway-ios/terminal/entry.ts`. The upstream pin and licenses remain sourced from `native/libghostty-vt` and the vendored font. The bundle carries both licenses and a manifest of input/output SHA-256 hashes. `node scripts/ios/build-terminal.mjs --check` detects stale inputs or modified assets in CI; Xcode does not require Node or fetch dependencies. Generated assets should be regenerated rather than hand-edited.

The WKWebView uses ephemeral storage and a `pathway-terminal://bundle/` asset handler restricted to its packaged index and assets. Content policy blocks external network, frames and resources. Navigation and window opening are restricted; terminal output is never evaluated as code. Only main-frame messages from the bundled page can request input/resize/copy or report ready/error. Remote transport remains in the native environment client. Output is queued outside SwiftUI state with a 4 MiB bridge bound; overflow requires reattachment rather than silently losing escape sequences. Stream cancellation, WebKit handlers, render callbacks and input tasks are cleaned up on navigation.

Focused checks: 23 file contract/server tests, 56 existing Ghostty core/surface/ABI tests (run from `apps/web` so its WASM test loader applies), and the native bridge command test pass. Swift syntax parsing and scoped TypeScript/lint checks pass. Native keyboard/selection/IME behavior on iPhone/iPad/visionOS and live remote PTY operation still require the integrated real-client pass.

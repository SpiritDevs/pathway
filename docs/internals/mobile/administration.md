# Native environment administration

`PathwayAdministrationView` accepts the signed-in account's company/environment registrations and environment-scoped RPC/HTTP transports. The HTTP transport receives an environment, HTTP method, exact path and optional JSON body. Project discovery uses GET `/api/projects`: the legacy `projects.list` method constant is not registered as a WebSocket RPC. Writes use `projects.mutate`.

Projects support attached directories, optional directory creation, defaults, scripts, and guarded local project removal. Provider cards show live availability, authentication, available models and the server's update capability. Provider sign-in uses start/complete/cancel flow IDs; authorization codes stay in view memory. Instance settings re-read the latest provider map and preserve opaque options and redacted secret markers. Legacy instances without an explicit settings envelope are not overwritten with guessed defaults.

Scheduled tasks use their typed structured schedule, model-instance identity, workspace strategy and access mode. Editing preserves provider options and workspace branch/origin settings. New tasks retain client identity for retries; enable/disable writes only the enabled field. The current service exposes latest run status/error/time and run count, not a paginated historical run log.

Usage is shown for one environment at a time, avoiding cross-environment transcript double counting. Token totals include output once; reasoning tokens are an output subset. API-equivalent costs are distinct from subscription spend. Unknown quotas remain unavailable, while known remaining percentages are clamped to 0–100. Failed refreshes retain previously read usage and identify it as an older snapshot.

Connection settings can test/reconnect through Pathway Connect, rename the environment, read trace summaries and revoke a company's environment registration. That revocation is not an account-level machine unlink. Direct LAN pairing, account relay-link provisioning/unlinking and new-phone setup are implemented by the separate [connection-onboarding flow](../native-connection-onboarding.md). Company members/teams/roles are separate from environment configuration.

Focused native tests cover schedule payload preservation and validation, usage accounting and unknown/exhausted quotas. Source parsing passed. Integrated platform build/tests, authenticated provider sign-in, remote operations, accessibility and visual review require separate verification. No live mutations were executed while implementing these views.

## Environment and source-control preferences

`PathwayAdministrationSettingsView` loads `server.getSettings` and returns only changed `ServerSettingsPatch` fields to `server.updateSettings`; the saved response becomes its new baseline. It covers provider-update checks, new-thread workspace/origin/base-directory defaults, generated-text/compaction/writer model selections, source-control writing style/templates and host background policy. Unchanged model selections retain opaque options. Selecting a different provider/model intentionally starts with its default options. Client-only preferences (including port-discovery range, queue/steer, timestamp, confirmation and grouping preferences) are not sent to this endpoint.

Scalar refresh interval edits use the contract's legacy millisecond leaves, which the server atomically merges into its current background overrides. Preset selection intentionally resets the full host policy. Advanced host-pause/monitor edits require the replacement-shaped `backgroundActivity.overrides` map: the view re-reads the latest settings immediately before saving and merges only edited keys into that snapshot. The existing contract has no revision precondition, so another client's simultaneous override edit between that read and write remains a concurrency boundary, also present in the desktop editor.

`server.discoverSourceControl` provides version-control and hosting-provider availability, Effect Option-wrapped version/account/host/details, installation hints and authentication status. The native screen supports refresh/rescan and deliberate account reveal. There is no hosting-provider authentication mutation in the current RPC contract; agent-provider login APIs must not be reused for Git-host credentials.

Seven focused `PathwayAdministrationSettingsTests` passed in an isolated Swift package using the actual model and JSON sources: unchanged/opaque model preservation, changed writing leaves, millisecond interval payloads, complete preset selection, fresh advanced-override merge, invalid values and discovery Option decoding. Swift source parsing passed; root owns the integrated Apple-platform build and client verification.

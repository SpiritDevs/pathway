# Subagent audit, 8 September 2026

The reported naming issue came from Codex's `subAgentActivity` ingestion. The adapter copied `agentPath`, such as `/root/audit_server`, into the subagent title. Child-thread creation reused it, so the conversation card and Lineage both displayed the path.

The fix derives a readable name from the final path segment when registering the subagent. `/root/audit_server` becomes "Audit server". Native thread IDs still determine identity and parent-child relationships. No model request, new wire field, or database migration is needed. Existing persisted titles remain as saved.

This was a source audit with focused automated verification. It did not include a live provider session or browser/device verification. Findings below are follow-up work, not changes included in the naming fix.

## Recommended follow-ups

1. **Handle every Codex activity kind explicitly.** The generated protocol includes `started`, `interacted`, `interrupted`, and `completed`. `registerSubagentActivity` handles the first and third, then treats everything else as interaction. A `completed` activity therefore leaves a running subagent running until a separate child `turn/completed` arrives. If that event is unavailable, the card stays active and `hasPendingBackgroundWork` keeps the session occupied. Use an exhaustive switch and define how completion evidence settles the task, card, and execution nodes without overwriting a known failure or interruption. Add a replay where completion is reported through parent activity alone, plus duplicate and late-event cases. See [the Codex adapter](../../apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts), `registerSubagentActivity`, and [the generated protocol](../../packages/effect-codex-app-server/src/_generated/schema.gen.ts), `ServerNotification__SubAgentActivityKind`.

2. **Distinguish reported child configuration from assumed inheritance.** The activity registration path supplies `model: null` and `reasoningEffort: null`. `registerSubagentThread` then initializes the child thread with the root input's model and options. This can display incorrect configuration when a child selects another model. Nested children also consult the original root input rather than their immediate parent's selection. The adapter does not subscribe to `thread/started`, so available nickname/role metadata is also missed; existing registration returns immediately instead of enriching metadata. Capture model and effort when the provider exposes them, distinguish unknown values from confirmed inheritance, and merge late metadata without resetting lifecycle state or overwriting a user's thread title. Test a child and grandchild with different models. See [the Codex adapter](../../apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts), `registerSubagentThread`, `registerSubagentActivity`, and `emitSubagentProviderTurnStarted`.

3. **Carry usage and activation history through the v2 projection.** `projectedSubagentsToRuntime` always sets `activationCount: 1` and `usage: null`. The v2 subagent contract has no fields for them. The Agents panel consequently cannot show these details for v2 agents, even though the older activity fold supports them. Add optional contract fields only where providers supply evidence, count actual activations, and preserve cumulative versus per-activation token semantics to avoid double counting. Unknown totals should remain unknown in the UI. See [the client mapper](../../packages/client-runtime/src/state/subagentRuntime.ts), `projectedSubagentsToRuntime`, [the contract](../../packages/contracts/src/orchestrationV2.ts), `OrchestrationV2Subagent`, and [the panel](../../apps/web/src/components/AgentsPanel.tsx).

4. **Replace scheduling retries for early child events with explicit buffering.** `rememberSubagentTurnStarted` buffers turn starts until registration. Item handlers instead call `awaitActiveTurn`, which yields up to 1,000 times and drops the item if registration has not happened. That makes early child messages depend on scheduling rather than registration evidence. Buffer unmatched child events with a bound and drain them when their thread registers. Test messages arriving before registration using a replay gate. The legacy [Codex session runtime](../../apps/server/src/provider/Layers/CodexSessionRuntime.ts) already contains child-notification buffering worth comparing. See [the v2 adapter](../../apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts), `awaitActiveTurn` and `rememberSubagentTurnStarted`. The dropped-message consequence is inferred from the code; it was not reproduced with a live provider in this audit.

5. **Test delayed resume across session release.** The adapter already documents that a completed child may resume later, while `hasPendingBackgroundWork` considers only running children. A sufficiently delayed resume can race idle session release. Add a deterministic session-manager test before changing the policy. Avoid pinning every completed agent indefinitely; any retention policy needs a bound or provider evidence that more work is expected. See [the Codex adapter](../../apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts), `hasPendingBackgroundWork`.

## Coverage and scope

| Area                      | Audit result                                                                                                                                                                                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entry points              | Chat cards, Agents panel, child-thread titles, and Lineage consume server-projected titles. Naming has no Settings, command-palette, or keybinding action.                                                                                                                                                           |
| Clients                   | Web and its Electron wrapper use the server titles. The native iOS subagent picker also renders the received title. No client-specific formatter is needed. Other clients consuming these fields receive the same change.                                                                                            |
| Providers                 | Only Codex's activity-path naming changes. Its older `spawnAgent` prompt naming remains intact. Claude, Cursor, Grok through ACP, and OpenCode keep their provider-specific title handling. Their capability declarations differ, so lifecycle controls should remain capability-driven.                             |
| Contracts and connections | Existing title fields carry the fix over local, remote, relay, and tunnel connections. No transport or environment identity changes.                                                                                                                                                                                 |
| Lifecycle                 | Existing adapter tests exercise interruption, late child starts during interruption, and resumed results. Replay scenarios cover ordinary, continued, activity-based, and nested subagents. Startup recovery already cancels stale subagent entities and linked nodes; this audit did not find that cleanup missing. |
| Performance               | Naming runs once at registration. No added model calls, subscriptions, animation, or repeated client work. Event buffering and session retention remain separate follow-ups with explicit bounds.                                                                                                                    |

Verification passed: 67 Codex adapter tests, four Codex subagent orchestration replay scenarios, and the server package typecheck. Replay assertions verify the readable name on the subagent record, parent card, and child thread, with nested identity and lineage preserved.

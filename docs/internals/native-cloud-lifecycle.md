# Native cloud synchronization lifecycle

`PathwayCloudModel` fences asynchronous work by lifecycle generation, membership identity, and per-company task identity. A page received after account shutdown, membership replacement, cancellation or a replacement sync worker cannot install entities or report an error for the new worker.

Authentication and transport shutdown run through one ordered task chain. Stop clears private in-memory content synchronously, before awaiting transport cleanup. A newer start waits for previous cleanup; an older stop has no later state mutation that could erase the newer account. Storage configuration uses its own identity plus the lifecycle generation both after shutdown and after cache loading. A sign-out during either suspension prevents the old cache from reappearing.

Bootstrap subscribes to the authorization head before walking pages. Pages must share one authorization epoch and captured snapshot version. A mixed epoch or a newer observed epoch discards the provisional snapshot and restarts from a null cursor. Higher epochs at the same version are significant and cannot be discarded as duplicate version updates. Ordinary version advances drain from the bootstrap's captured version, matching the backend snapshot contract without repeatedly restarting active workspaces.

Authorization changes clear the installed replica and cursor before starting fresh bootstrap. Expired or differently authorized change pages take the same path. Change workers are independently identified and cannot clear a replacement worker's handle. Company removal clears both bootstrap and drain task identities. Environment events, deferred cache metadata, and lifecycle metadata responses also check their owning generation.

The internal `PathwayCloudSyncClient` protocol adapts the existing Convex client without changing its network contract. Internal `received(companies:)` and `received(head:companyId:)` functions are the subscription input boundaries. Tests can drive those inputs deterministically and release individual transport responses through continuations.

Nine focused tests in `PathwayCloudLifecycleTests.swift` cover mixed bootstrap epochs; repeated same-version epoch changes; replaced memberships; late revoked drain responses; expired cursor clearing; normal version catch-up; ordered shutdown/authentication; overlapping account storage configuration; and sign-out during pending storage setup. Tests use observation and transport continuations rather than sleeps or polling. The isolated SwiftPM harness compiled the checked-in CloudModel, cache, and supporting native models with a stubbed Convex SDK and Issues adapter. This proves lifecycle behavior, not real Clerk/Convex traffic; integrated platform builds and signed-in device execution remain separate checks.

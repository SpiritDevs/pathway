# Orchestrator inspection, handoffs and routing

Coordinator reasoning still returns typed decisions. Direct `inspect` actions now support project directory listings, line-based text-file reads, visible thread excerpts and public web search. These do not create a worker thread. Mutations validate the coordinator, workspace, project, environment and conversation audience; the owning environment reads the requested data and returns it to the original job. Access is checked again before delivery and before including results in context. Inspection records are private coordinator state and never enter the company command feed.

Inspections have a three-minute deadline and each result is limited to 16,000 characters. A request can make at most twelve inspections. Directory and file reads are bounded, canonicalized to the selected project and exclude `.git` and `.pathway`. Visible thread excerpts support paging; system and streaming messages are omitted. The original job resumes when its results arrive or reports unavailable reads after their deadline. Expired reads are excluded from environment discovery.

Codex and Claude can perform public web searches in an isolated temporary directory with other tools disabled, under the conversation's allowance guard. Codex enables its live web-search tool while disabling shell, editing, MCP, apps and plugins. Claude exposes only WebSearch with an empty MCP configuration. OpenCode, Cursor and Grok do not currently expose this restricted search mode; they fail explicitly. Supported coordinator providers can use the environment's direct file and thread reads independently of provider tools.

Every new assignment and follow-up includes a factual handoff requirement: outcome, evidence, changes/artifacts, verification and remaining work. Workers are asked to keep the report below 24,000 characters. Automatic collection preserves up to 32,000 characters of the final answer and marks truncation. Context prioritizes recently updated reports within a 64,000-character total budget and marks omitted report content for explicit retrieval.

`continueThread` validates the existing thread and dispatches a durable `sendMessage` command to its original environment. It creates an assignment record for the new request, not another thread. Busy threads queue the message after their active run. The command-derived message ID identifies the exact run whose report must be collected, so an earlier completion cannot satisfy the follow-up. Conversation allowance limits are inherited by the target thread. Cancellation targets the follow-up's queued or active run and does not interrupt an unrelated run ahead of it.

Automatic thread, issue and environment signals are grouped by the coordinator owner's audience. Clear project ownership selects a project coordinator; environment-wide changes prefer the personal coordinator. If several equally scoped contacts remain, a routing job uses the provider's existing lightweight text-generation default (Luna at low effort for Codex; Haiku for Claude). It receives only a bounded activity description and candidate responsibilities and selects one ID. A timeout, invalid response or unsupported routing provider uses a stable eligible fallback. Election commits under the normal job lease and rechecks access; event receipts prevent repeated or coalesced delivery from creating a second responder. Other owners retain their own authorized notifications.

Direct human messages continue to target their selected contact or group lead. Completed specialist group replies no longer automatically wake the lead. An explicit message action requests a decision or consolidation when required. Collaboration can still ask multiple project specialists for distinct contributions.
